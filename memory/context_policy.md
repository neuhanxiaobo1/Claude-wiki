# Context Policy

本页保存论文知识库的轻量上下文预算与历史压缩规则。它不替代 `AGENTS.md`，也不新增专门 agent。

## 目标

- 避免长期对话后丢失项目目标、已确认决策和下一步任务。
- 避免把过期对话当成当前规则。
- 在上下文变长时，把稳定信息沉淀到文件中，而不是依赖聊天历史。

## 增量读取与恢复

启动入口遵循 `AGENTS.md`，本页不增加每轮必读清单。

| 情形 | 读取范围与停止条件 |
|---|---|
| 首次进入或缺少基本上下文 | 按 AGENTS 读取公共规则、项目配置，通过 index 定位对象；无需预读全部 agent、模板和综合页 |
| 同一任务继续 | 复用已读且无变化迹象的规则、证据和状态；只读新增输入及受影响文件 |
| 跨阶段或压缩后恢复 | 先看本页当前任务，再查对应计划与最近相关日志；能够确定对象、范围、完成条件和下一步后停止回溯 |
| 局部论文修订 | 读取指定论断依赖的原文、方法定义和图表，以及必要的本页上下文；不默认重读七篇论文或全部大纲 |
| 文件变化、记录冲突或信息缺失 | 重读冲突或缺失部分；仅当缺失信息影响正确性或授权范围时询问，并继续独立工作 |

当前用户指令优先于历史状态。快照与实际文件不一致时，核对最近相关日志、计划及文件变化，不凭文件日期猜测哪个科学结论成立。研究目标由 project_profile 保存；科学证据仍须回到来源。

## 压缩触发条件

出现以下情况时，可更新短上下文，减少后续回溯；不因此启动额外整理任务：

- 对话已经跨越多个阶段，且后续任务仍依赖早期决策。
- `log.md` 最近新增多条初始化或结构变更记录。
- 阶段完成，需要留下明确的下一阶段入口。
- agent、template、memory 或 synthesis 规则发生结构性变化。
- 发现当前回答依赖很早的聊天历史，而不是项目文件。
- 出现规则冲突、命名冲突或任务边界不清。

## 压缩后应保留的信息

压缩时只保留：

- 当前对象、任务类型、授权范围、完成条件和下一步。
- 已完成内容、未决项、必要文件入口和最近相关记录。
- 仍影响当前任务的用户约束与被否定方案；用链接指向详细决策和偏好，不复制全文。
- 证据版本、已核查范围和待核查项的定位；不得把压缩后的科学判断当成新的证据。

不要保留：

- 已完成的详细过程。
- 临时讨论但未采纳的想法。
- 重复的中间解释。
- 与论文知识库无关的内容。

## 写入位置

- 当前任务与恢复入口：本页“当前任务”；阶段细节和验收记录：对应计划。
- 用户已确认的研究目标、来源配置和语言偏好：`memory/project_profile.md`
- 科学主张、证据关系与研究假设：`synthesis/core-argument-map.md`，仅在任务需要时读取；旧版混入的操作待办不作为当前执行指令。
- 默认输出风格：`memory/style_snapshot.md`
- 结构性决策：`memory/decision_log.md`
- 具体操作流水：`log.md`
- 错误和修正规则：`memory/error_log.md`

## 使用规则

- 不确定的信息标注为“待确认”。
- 压缩本身不改变规则、用户研究目标、科学结论或核查状态。
- 压缩不等于删除历史文件；只是在后续任务中优先读取短上下文文件。
- 当前任务只在获授权的工作完成、范围变化或交接时更新；普通只读问答无需机械写盘。保留短状态，完整过程追加 log。
