# Hard Memory

本页保存 ResearchWiki 长期稳定、默认不可违背的通用规则。具体研究领域、用户目标、Zotero 设置和写作偏好写入 `memory/project_profile.md`。

## Project Boundary

- 本项目默认只面向论文知识库。
- 原始资料以论文 PDF、论文导出的 Markdown、补充材料、图表附件和论文阅读笔记为主。
- 不主动扩展到商业资料、医学病历、个人日记、会议纪要或其他非论文知识库来源。
- 如果用户要求扩展边界，先记录为“待确认”，不要直接改写项目规则。

## Layering Rules

- `raw/` 保存原始资料。除非用户明确要求，不修改、不删除、不重命名原始文件；Zotero PDF、缓存全文、译文及补充材料同样按原件保护。
- `raw/zotero_imports/` 中由本系统生成的 import_plan/manifest 属于导入管理记录，可在已授权导入任务内按 import_zotero 规则同步更新；这不授权修改其他原件或 Zotero 条目。文件身份不明时先核实。
- `wiki/` 保存结构化知识页面，例如 paper、author、topic、method、dataset、metric、claim、gap 和 review。
- `synthesis/` 保存跨论文综合成果，例如 literature map、open questions、research positioning 和 review outline。
- `memory/` 保存长期规则、项目配置、错误记录、标签体系和术语别名。
- `agents/` 保存任务型操作规程。
- `templates/` 保存输出格式模板。

## Evidence Rules

本节是阅读、入库、综合、gap 和写作共用的质量底线。任务文件提供具体步骤，不能因模板已填满或页面已入库就省略判断。

### 1. 分开证据类型、支持程度和核查状态

| 维度 | 记录方式 |
|---|---|
| 证据类型 | 直接观察/测量；计算/模型输出；作者机制解释；转引文献；AI 推断。一条论述包含多类时拆开说明 |
| 支持程度 | 对具体论断在声明条件下支持充分、部分支持或证据不足，并说明关键理由；不以论文数量、期刊或单个形容词代替评价 |
| 核查状态 | 已核查及实际范围、待核查、因材料缺失暂无法核查；注明缺失影响。已核查不代表结论必然成立 |

新旧页面均可先用明确正文表达，不要求此阶段批量迁移字段。原有 strong/weak 或 confidence 必须能够对应到具体论断与理由；`AI 推断` 不是强度等级，`待核查` 也不是低质量的同义词。

### 2. 核心结论的最小证据要求

- 绑定研究对象、必要条件/对照、指标定义、结果及来源定位。数值保留单位、近似性、误差与含义；未报告的信息写未报告，不补造。
- 定位到具体章节、图表、公式或页码；claim 通过论文页追溯也可以，但旧摘要、大纲、日志及快照不能充当原始证据。
- 分清正文版本、译文、补充材料和视频；如仅读摘要、图注或视频说明，声明实际覆盖，不写成已完整检查对应材料。
- 关键数值、单位、样品标识、公式、趋势方向有歧义时回查原始文件。来源内部矛盾无法解决时记录不同表述及位置，限制结论，不擅自修正原文或选择最符合旧主线的一项。
- 先从原文提取结果，再对照旧知识页。原始数据、作者解释和本次评价分开；新总结的确定性不能超过支撑证据。

### 3. 从结果到结论的判断边界

- 相关性不自动证明因果；评价机制时检查控制变量、采样/检测范围和足以改变结论的替代解释。未观察到不等于不存在，单个局部表征不等于排除全部机制。
- 计算结果保留模型假设，不能改写为直接实测或已验证服役表现；作者合理解释可以保留为解释，不必因尚未证明就否定其全部价值。
- 对比前核对指标定义、实验条件、对照来源和数据独立性。不可比数字不直接作排名、倍数或统一拟合；只能定性比较时明确边界。
- 多篇转引同一数据不算多次独立验证。未读原始引用时标明转引；单篇研究也可以充分支持一个限定实验事实，不机械要求多篇。
- “显著、首次、最佳、普适、全面优于”等表述须有对应统计、检索或比较依据。多目标性能分别报告收益和代价；无法确认首创性不妨碍准确陈述论文贡献。
- 本文未研究、当前语料未覆盖与全领域尚未解决分别处理。领域 gap 须说明检索范围和反证；未检索时只作为候选问题或语料缺口，不自动生成确定 gap。
- 综合与大纲以证据和研究问题组织；核心前提不成立时调整或撤回主线，不改写证据来适配旧叙事。不把 AI 生成的研究定位冒充用户目标。

### 4. 未决信息与下游结论

- `processed` 或“已入库”仅表示处理状态，不保证所有结论已核实。关键证据缺失时可以保存已确认部分和草稿，但未决判断不能作为确定依据进入 claim 或综述。
- 修正源结论时，检查直接引用或明确依赖它的页面，记录受影响判断、原因及来源链接。有本轮授权时做最小修正或标记待复核；不默认重写全部关联页。
- 若用户限定不能修改下游页面，在允许的源页或维护记录中列出待复核清单。后续使用这些判断前须解决已知问题；不能因为尚未写入下游标记而继续采用旧结论。
- 待复核按论断处理，不必使整篇论文失效。未经实际检查不得标为已通过；不确定性应紧邻对应判断，不能只放在文末统一免责。

## Maintenance Rules

- 每次重要操作后追加 `log.md`。页面成员、路径、索引说明或重要状态变化时更新 `index.md`，否则只核对一致性。
- 新增标签前先查 `memory/tag_taxonomy.md`。
- 新建 topic、method、dataset、metric、gap 或 claim 前先查 `memory/term_aliases.md` 和已有页面。
- 一旦发现错误，或用户指出错误，必须更新 `memory/error_log.md`。
- 不追求一次性完美，追求持续更新、持续纠错、持续形成研究地图。

## Output Rules

- 默认使用 `memory/project_profile.md` 中指定的语言、术语和引用偏好。
- 如果 project profile 尚未填写，默认用中文、学术简洁风格输出，并把缺失项标注为“待确认”。
- 页面应尽量使用 YAML frontmatter，方便 Obsidian Dataview 查询。
- 入库须检查真实知识关系；按本轮范围更新相关页面或列出待复核项。无明确贡献或证据时，不为填模板强行创建 method、claim 或 gap；局部修订只改受影响内容。
