# 多研究方向知识库改造方案

本方案依据用户 2026-09-09 的需求：教授同时开展多个研究方向，保留当前陶瓷腐蚀方向的积累，新增方向有独立规则、资料、总结和记录；不同方向允许明确借鉴，每次开始研究工作时选择继续某方向或新建方向。

当前进度：阶段0–4已完成各自声明范围工作；第二个实际方向见 [[docs/migration-stage4-2026-09-09/report]]。阶段5的首篇电子封装真实论文入库已完成，见 [[docs/optimization-stage-d-2026-09-10/report]]；独立新会话、Obsidian桌面、跨方向借鉴和备份恢复仍待真实案例验证。阶段2目录/规则已切换，旧screening.csv因Windows占用留有退役副本待清理，见 [[docs/migration-stage2-2026-09-09/report]]。阶段1材料保留为迁移前快照；后文阶段0/1当时边界是历史说明，不代表当前仍使用旧目录。

## 1. 架构选择

采用一个 Obsidian vault、一个仓库、多个方向工作区。根目录保存共用规则和管理入口；`directions/<direction_id>/` 保存一个方向的完整研究资料和运行记录。先保留现有 agents、templates、memory 的分类，避免为分层再引入一套陌生目录。

方向隔离包括读取范围、写入范围、研究目标、任务状态、术语含义、综述叙事和记录归属。文件夹隔离是基础，任务路由和规则加载才决定实际行为。本方案是工作流隔离，不是操作系统访问权限隔离；如果未来需要学生之间的保密或权限控制，应另设仓库/vault 和访问权限。

跨方向共用通用方法与资源入口，但每个方向独立判断其适用性，不共用一份可被任意方向改写的科学总结。

## 4. 规则的生效方式

公共证据底线始终适用。方向规则可增加领域核查项、定义研究范围、指定阅读/总结重点与写作风格；不能把推断改称实测、降低来源要求或自动提升 checked 状态。默认偏好可以被方向设置覆盖，已执行的研究任务还须服从本轮用户明确的对象与范围。

每次任务只加载：公共启动规则 → 所选方向配置与短上下文 → 对应通用任务流程 → 该方向适用补充规则/模板。嵌套 AGENTS 作为方向入口仍需显式读取，不能只依赖工具是否自动加载。

通用任务文档中的研究路径统一使用 `D/` 表示已选方向根目录，公共规则路径使用仓库根目录。执行前将 D 解析为明确路径；D 未确定时不写研究文件。模板占位符生成后必须展开，不能把 `D/` 写成真实 Obsidian 链接。

知识页双链使用相对于 vault 根目录的完整路径，例如：

```text
[[directions/ceramic-corrosion/wiki/topics/Ceramic Corrosion]]
```

方向知识页逐步添加 `direction_id` 字段用于筛选与校验；所属文件夹是归属依据，字段必须一致。原始资料不为补字段而修改。允许不同方向分别存在同名 topic/method 或同 DOI 的论文解读页；去重不能把这些页面跨方向自动合并。

## 5. 开始、继续与切换方向

每次新会话或新一轮研究工作，在用户未明确指定方向时，先读公共入口和方向注册表，再提供一次简短选择，例如：

```text
请选择本轮研究方向：
1. 继续「陶瓷腐蚀」（最近使用；当前有 10 篇论文，暂停扩写）
2. 继续「已登记的方向 B」
3. 新建研究方向
```

上述 B 是展示示例，实际菜单只列已登记方向；具体科研进度可在选择后显示，避免为展示菜单预读所有方向。最近使用仅用于排序，不代表本轮已选择。用户回复前，方向相关读取和写入等待；公共规则维护可以继续。

- 同一会话内已选方向、同一任务继续：沿用选择，不每条消息重复问。
- 用户明确点名方向或给出可唯一归属的方向文件路径：直接进入，简短声明本轮方向。
- “继续之前的工作”在新会话中不能仅凭全局最近记录自行决定方向，应展示选择。
- 用户明确要求维护总规则：进入公共维护范围，无须先选择科研方向。
- 用户新建方向：获取名称与基本范围，生成唯一 ID、骨架与注册项；其余未知设置留待填写，不能继承陶瓷腐蚀目标、Tian 作者口径或 Scopus 清单。新名称语义重叠时先检查已有方向，避免误建重复。
- 用户切换方向：保存原方向短交接，重新绑定 D，读新方向规则；旧方向科学结论与偏好退出当前任务依据。工具写入前检查实际路径属于本轮允许范围。
- 同时打开多个会话：每个会话自行绑定方向，不能用一个共享的 active_direction 文件控制全部会话。注册表的最近使用变化不切换其他会话。

方向注册表只保存 ID、名称、路径、状态、最近使用时间等导航信息。详细进度只在各方向 `current_context.md` 维护，避免重复记录漂移。

该菜单由工作入口规则引导对话提供，不是仅靠 Markdown 就能自动弹出的桌面窗口。本轮不引入额外插件或可视化启动器。

## 6. 跨方向借鉴

默认检索范围是当前方向。需要其他方向资源时，按具体论文、方法或问题定向读取；可以查公共资源目录，不主动加载其他方向全部上下文。若任务明确是跨方向比较，应先界定参与方向、读取对象和输出归属；未指定归属且会改变交付位置时再询问。

例：方向 B 借用陶瓷腐蚀中的层叠筛选方法，应在 B 的方法/论文页记录来源完整链接、来源版本或核查日期、原适用条件、B 中拟借用部分及不能直接迁移的假设。借鉴是否可行标为已核查、待核查或 AI 推断；不能把 A 的实验结果当成 B 的实测结果。

- 同一论文：原始来源可以引用同一个已核位置；B 保存面向 B 问题的独立卡片，并记录共同来源身份。资料缺失时明确缺失，不强制复制外部缓存。
- DOI/附件身份相同的跨方向页面属于同源材料，不作为独立验证重复计数。
- 来源方向页面默认只读；借鉴任务的结论、日志、待核查只写接收方向。
- 发现来源错误时，在本轮接收方向限定/撤回受影响结论并记录具体来源待复核，不自动修改其他方向。已明确授权跨方向修订时，分别维护各方向记录。
- 后续复用前检查已知未决和来源变化；公共资源目录只作导航，不能替代证据。必要时在维护任务中检查跨方向反向链接，不为一次来源更新启动整库重写。
- shared 初期只放可复用资源入口和条件说明。领域 claim、gap、大纲与研究定位继续归属方向；不因“可能有用”升为通用知识或总规则。

## 8. 迁移细则与回退

1. 先记录 Git 工作区状态和可用版本基线。Git 不包含全部原件和忽略文件，不能单独充当完整备份；本地迁移备份应包含实际需迁移文件与校验清单，不自动上传。
2. 迁移清单覆盖 Markdown、CSV、JSON/manifest、图片附件、`.gitkeep`、README 及隐藏配置。真实论文数量按页面类型计，排除 `.gitkeep`，当前是 10 篇而非文件计数的 11。
3. 原件迁移仅改变已授权范围内的位置，不改内容；先复制、核对文件数/哈希和引用，再切换入口，旧副本在验收前保留在明确的非工作备份位置。外部 Zotero/MinerU 缓存位置保留，不递归搬动外部资料库。
4. 移动/清理前解析完整源/目标路径，核对均在清单和允许目录内。目录有新增或冲突时先处理差异，不覆盖、不使用未经核对的递归删除。
5. 按映射修复实际双链、Markdown 相对链接、图片嵌入、YAML 路径和管理记录；保留显示别名、标题/块锚点及 E# 引用含义。历史日志中的旧位置可保留为历史文字，并提供映射；仍承担跳转的链接需修复。
6. 活跃入口必须唯一，不能长期保留两套可继续写入的论文页。不得用空壳知识页或广泛路径替换掩盖断链。
7. 同步 `.gitignore` 的 `directions/*/raw/` 覆盖和备份忽略规则；核对派生 CSV 与原始私有 CSV 的区别。当前 raw 规则以根目录为前缀，不能假定它会继续保护新目录中的 JSON/MD。
8. 更新 Obsidian 当前 `path:wiki/` 图谱过滤与最短链接策略，提供方向路径过滤方式；共享 vault 的设置会共用，图谱显示不作为隔离机制。
9. 回退使用迁移映射和完整本地备份恢复目录、公共入口与配置，仅撤回本次迁移；保留迁移后可能新增的用户文件。不使用 reset --hard 或覆盖整个工作区来代替有范围的回退。

## 9. 验收清单

- 原件数量与内容哈希一致，论文 10 篇及原有 claim/gap/topic/综述数量与身份一致；科学正文除链接/归属等机械调整外无意外变化，证据状态不升级。
- 对比迁移前后链接基线：无迁移新增断链、歧义短链、失效附件路径；已存在的问题单列，不冒称本次已全部解决。
- 总规则中无生效的陶瓷、CMAS、Tian 分类或特定 collection 要求；方向规则通过明确入口加载。历史说明与示例单独识别，不以全文无关键词作为验收。
- 新会话未选方向时展示菜单且不写研究文件；已指定方向直达；同一会话不重复问；两个会话不会互相切换工作目录。
- 新方向不继承旧目标、论文、进度、领域标签、组内外口径或总结叙事；公共证据底线与默认模板仍可使用。
- 同名方法可在两个方向独立存在；跨方向复用保留来源、适用条件和独立评价；单方向任务的文件变化清单不出现其他方向改动。
- 每个方向的任务、错误、研究决定落本方向；根日志仅记公共维护；跨方向任务记录其实际涉及范围。
- Git 忽略规则用新路径样例实际检查；上传范围不因迁移扩大。配置文件可解析，Obsidian 实际显示若未启动验证须明确列为未测。
