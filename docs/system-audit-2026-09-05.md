# 知识库系统检查（2026-09-05）

用户要求暂停论文修改，先检查系统。本轮只记录诊断与建议，不重构规则。

## 判断

三层目录可以保留。主要问题是启动读取过重、缺少局部修订流程、研究判断重复维护，以及缺少证据依赖和结构校验。它们会增加执行成本，但本次未测量模型延迟，不能给出各因素的耗时占比。

执行者也有责任：重复读取已有上下文、把单篇修订扩大为整页重写、输出批次过大被截断，以及使用不被工具接受的补丁。这些不是系统必然要求。

## 问题与依据

1. **启动过重。** AGENTS.md §3 要求任何任务前读取八个文件；各 agents 再次列出相同要求。检查时合计 31,896 字符，其中 log.md 为 14,089 字符。缺少“首次启动／同任务继续”的区分，也未明确已读未变文件可以复用。
2. **缺少局部修订路径。** pdf_read_agent.md 同时负责生成和更新，但没有为“只修正已有结论”定义较小输入及输出范围。AGENTS.md 的联动维护要求又容易被解释为必须立即更新全部关联页。
3. **模板重复。** pdf_ingestion_template.md 与 paper.md 重复摘要、方法、创新、实验、claim、gap；paper 内同一结论也重复多次。没有规定完整模板只适用于首次入库，修改已有段落可以局部完成。
4. **纠错传播机制缺失。** paper、claim、topic、synthesis、index 和 core-argument-map 多处保存同一判断，却没有来源版本、依赖关系和 needs-review 状态约定。源结论修改后，下游仍可能使用旧结论。
5. **证据类型不够明确。** claim 模板有来源和强度，但未要求区分直接实测、作者解释、转引前文和 AI 推断；gap 没有单列领域新颖性核查状态。现有半径 claim 的“六篇独立支持”就是应复核的实例：前期原文核查已发现后续论文引用同一 2019 数据。
6. **上下文快照混合了事实判断与任务状态。** context_policy 建议读最近日志，但 AGENTS 没有相应范围限定；core-argument-map 同时保存研究主张和当前任务，容易使尚待纠正的结论成为下一轮推理前提。
7. **结构检查不足。** 七篇论文 YAML 均可解析，但 2022 高熵单硅酸盐论文的 type 是 topic，且 frontmatter 缺 title、doi、zotero_item_key、source。lint_agent 未明确要求目录/type/必填字段一致性检查。此错误尚未修复。
8. **综合研究边界不足。** project_profile 的核心问题为“暂无”、排除范围待填，综合页却已形成具体定位路线。综合任务因此缺乏收敛条件；这不应阻塞普通论文阅读。

## 建议顺序

1. 先明确启动读取边界、已有论文局部修订流程，以及下游先标待复核的规则。
2. 再简化模板，增加证据类型、实验条件、指标定义和来源定位。
3. 最后补基础结构检查，分开保存任务状态与研究结论。
4. 恢复 2019 论文逐节修订，用小任务验证流程。

无需推翻目录、增加更多 agent 或强制增加人工审批。以上为建议，尚未实施。
