# 中断恢复、并行修改与备份范围

本页落实根AGENTS的作用域、原件保护和记录规则，是执行约定，不提供后台锁、自动备份或文件系统隔离。当前状态仍在所属范围短状态中维护，不新增全局active_direction。

## 中断后恢复

先读短状态及必要近期log，核对对象、授权范围、实际文件、已完成边界与剩余工作，能确定下一步后停止翻历史。不能仅因日志写开始就重跑，也不能仅因文件存在就认为内容完成。

| 中断位置 | 恢复方式 |
|---|---|
| 新建方向前 | 核对注册表ID、规范路径、名称和范围 |
| 骨架部分写入未登记 | 凭创建记录/快照确认属于本次授权，核对成功部分，只补缺项；不覆盖来源不明的同名目录 |
| 骨架完整未登记 | 核对必要入口及方向内容后再登记、补根导航与主log |
| 已登记而入口/记录未同步 | 以实际文件和最近操作证据补本次缺项，不重新生成整个方向 |
| paper已写而清单未同步 | 核对身份和实际完成范围，只据成功结果更新生成的manifest/import_plan；不重复建页、不提前标checked |
| paper已修正而下游未完成 | 先限定失效判断，再处理允许的直接依赖；范围外列具体未决，不重做全部阅读 |
| 批次部分完成 | 按稳定编号/身份列成功、未完成及失败原因，继续剩余已授权对象；不重用编号或清空清单 |

新方向仍先核对完整骨架再登记；部分骨架续建只适用于能确认归属和授权且无新冲突的目标。来源不明的部分先消歧，其他独立工作继续。

## 写前核对与并行修改

1. 准备修改时保留读入内容/哈希；新文件记为预期不存在。重要规则调整可保存范围明确的本机快照，不为普通只读问答建立备份。
2. 写前再核对真实路径、文件出现/消失和版本是否与读入一致。发现漂移先比较双方修改，只合并无冲突段落，不整页覆盖。
3. 同页面、共享注册表/索引并行修改时先协调文件归属和顺序；冲突部分暂停，继续无依赖工作。哈希比较不能消除比较后立即发生修改的竞态，也不能代替写入锁。
4. 多文件操作分阶段验证实际输出后更新短状态；中断时保存成功边界。已有明确授权不因重试而逐项重问。
5. 回退先核对快照范围及后续改动，仅恢复相关段落/文件；不以整库reset、旧迁移脚本或覆盖复制抹去其他任务成果。恢复规程不授权改动原件。

## 后续恢复验收

目前未指定独立备份目的地/频率，不自动建立同步或计划任务。下一阶段先明确允许备份的目录、来源版本、目标位置和覆盖范围，再实施；本页不授权向任何外部位置传输。

恢复演练在独立空目录：确认备份清单/哈希，恢复指定样例，再核对路径、字节、来源定位和必要链接，原工作库不覆盖。分别报告Git知识文件、管理记录、本地原件和外部资料的可恢复/未验证范围。真实恢复演练尚未执行，不能将结构检查通过替代恢复成功。
