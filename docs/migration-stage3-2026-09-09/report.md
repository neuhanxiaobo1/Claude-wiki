## 入口规则逐案检查

| 输入情境 | 核对到的执行规则 | 结论 |
|---|---|---|
| 新研究会话仅说“继续之前的工作” | 根AGENTS第2节先列注册方向与新建选项，未回答不读取各方向研究全文或写研究文件 | 规则覆盖 |
| 点名已有方向或提供唯一归属路径 | 绑定D、显式读D/AGENTS与profile/current_context，直接执行已授权任务 | 规则覆盖 |
| 同一任务继续 | 复用选择和未变上下文，不重复询问 | 规则覆盖 |
| 新建方向 | 名称/基本范围、稳定ID合法性和目标冲突先核对，未知领域要求沿用公共标准，不复制旧方向语料 | 规则覆盖 |
| 切换方向/两个会话 | 保存必要交接；会话独立绑定D；last_used仅导航，不设置全局active_direction | 规则覆盖 |
| 新增领域标签 | 只登记D/memory/tag_taxonomy，不将领域词条并入公共词表 | 审查发现旧句矛盾，已修正 |
| 公共规则或架构检查 | 无须绑定科研方向，只读所需公共规则并写根维护记录 | lint开头歧义已修正 |
| 借鉴其他方向、来源有误 | 来源默认只读，接收方向独立评价；先限定当前结论，待复核放允许写入的位置 | 规则覆盖 |

## 验收边界与下一步

文件路径与记录分隔已实测，入口和切换行为属于规则逐案审阅；没有启动独立Agent会话验证每次自动加载行为，没有运行Obsidian桌面或新方向真实论文。Markdown规则不是文件系统权限控制，不能阻止不遵循规则的其他程序写入。
