# 多研究方向工作流程

## 开始与切换

可以说“继续陶瓷腐蚀方向”或“新建研究方向：名称，基本范围”。未指定方向的新研究会话由根AGENTS展示已有方向与新建选项；同一任务已选方向时不重复询问。公共规则维护无需科研方向。该选择由对话规则提供，不是桌面自动弹窗。

每个会话独立绑定方向路径。方向选择后读取该方向AGENTS、profile和current_context，再按任务加载通用流程及本方向扩展。切换方向保存必要交接，重新加载配置；不继承另一方向的目标、模板差异或任务进度。

方向profile中的默认单篇/批次偏好用于尚未明确对象或范围时安排工作；用户已指定单篇、清单编号范围或明确批次并要求处理时，按现有授权继续，不在每篇或每个阶段重新索取同一确认。对象歧义仍按实际影响消歧，不能用“不重复确认”跳过来源身份核对。规则出处见根AGENTS第3节。

## 新建方向

1. 取得名称与基本范围；若语义与已有方向重叠，检查是否用户意在细分或另建。稳定ID用英文小写与连字符，建议符合`^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`，禁止路径分隔符、点段或绝对路径。
2. 核对注册表ID不重复、目标`directions/<id>/`不存在；解析完整目标路径确认位于directions内。显示名称可修改，ID作为稳定路径不随名称自动改变。
3. 按templates/direction.md创建AGENTS、index/log/inbox、必要memory、raw/wiki/synthesis/docs目录。没有材料时不建立占位论文、claim或gap。专业阅读/总结/写作规则未知时明确沿用通用标准。
4. 名称、范围与已明确偏好写方向profile；不得复制陶瓷或其他已有方向的目标、团队口径、来源collection、术语、文章或任务状态。
5. 验证方向入口/路径后，将ID、名称、路径、status写入memory/direction_registry.yaml并更新根index与根log。last_used未知用null；实际进入研究任务后才写当前日期/时间，不拿上次方向推定本轮选择。
6. 缺少引用风格等非关键配置可留待确认；论文身份或范围不明且会改变任务正确性时才询问。没有新方向论文授权不自动导入或开启检索。

创建中断时按[恢复说明](recovery-and-backup.md)核对部分骨架归属，只续写本次缺项，不覆盖来源不明的同名目录。登记前确认完整入口；并行编辑注册表时核对写前版本，保留其他任务新增项。

## 跨方向借鉴

按具体论文、方法或问题定向读取来源方向。接收方向写自己的评价，记录来源完整链接、版本/核查日期、原条件、拟迁移部分和限制。另一方向默认只读；共享来源不是独立验证，不能将A的实测结果写成B的实测结果。

shared/resource_catalog只导航可复用入口，不代替原文。发现来源已知错误时先限定接收方向判断并记录待复核；另行有跨方向修订授权时分别维护相关方向。

## 记录与使用边界

根目录公共文件可为方向导航，但研究内容与记录都在方向内。方向隔离是工作流边界，不是操作系统权限；共享Obsidian设置和注册表不决定会话正在处理的方向。查看图谱可按方向路径过滤，不能把图谱显示范围当作写入授权。
