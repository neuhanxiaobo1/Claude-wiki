# 论文知识库规则审视与分步完善计划

本计划补充 [[docs/system-audit-2026-09-05]]，重点从执行效率扩展到论文阅读、证据评价、结论生成、入库与综述可靠性。当前状态：**第 1 阶段已完成（2026-09-05），第 2–9 阶段待实施；论文修订继续暂停。**

## 1. 审视范围与总体判断

已阅读或复用本次连续检查中已完整读取的文件：

- 入口：AGENTS.md、CLAUDE.md、README.md、QUICKSTART.md。
- 六个任务规则：import_zotero、pdf_read_agent、synthesis_agent、gap_agent、review_agent、lint_agent。
- 七个模板：pdf_ingestion_template、paper、claim、gap、topic、method、review。
- 八个 memory 文件：project_profile、hard_memory、context_policy、style_snapshot、tag_taxonomy、term_aliases、error_log、decision_log。
- 配套说明：initialization、zotero-workflow、obsidian-setup、privacy-and-gitignore，以及 .gitignore。
- 状态与实际产物抽查：index、log、inbox、core-argument-map，七篇论文的 YAML，以及前期原文复核发现的典型错误。

本轮是完整规则体系审视，**不是七篇论文重新修订、全文事实审核或全库链接审计**。没有测量工具或模型延迟，不推断耗时比例。

现有系统并非没有质量原则。AGENTS/hard_memory 已要求来源与不确定性；claim 已有 Scope 和反证；gap_agent 已禁止将“论文未做”自动等同于重要 gap。问题在于，这些原则没有形成可操作的判断步骤和验收条件。执行者也未充分遵循已有约束，不能把已发生的错误全部归因于规则缺失。

应保留：三层目录、原始资料保护、来源追溯、真实双链、用户指定研究范围、单篇渐进入库和历史记录。应完善的是从证据到结论的流程，避免单纯增加更多文件、agent 和重复检查。

## 3. 拟建立的论文解读流程

### 3.1 明确任务和资料身份

先确定是新入库、完整复核、局部修订、综合还是写作；指定目标论文/小节、预期输出及本轮修改范围。已有论文不重复建页；已知 PDF 或缓存可直接进入阅读，不重新生成候选清单。

核对题名、DOI 或可用标识、父条目、附件及版本。正文、译文、补充材料、视频、预印本和正式版必须区分；没有 DOI 或非 Zotero 来源是合法情形，记录缺失原因即可。来源规则应保留现有 connector 与原始资料边界，不因追求便利默认绕过限制读取数据库。

### 3.2 阅读覆盖与回查规则

- 首次完整入库：读摘要、研究问题、方法、结果、讨论和结论；同步看支撑核心结论的图表与必要补充材料。
- 局部修订：读该论断依赖的上下文、方法定义、图表/公式及对应讨论；只有发现影响更广时扩大范围并说明原因。
- MinerU 可用于主体阅读，关键数值、单位、样品编号、公式、趋势方向或翻译有歧义时回查 PDF。正文与图表矛盾时记录双方位置，不静默选一个。
- 视频说明不能等同于已观看视频，图注不能等同于已检查图中数据。补充材料不可得时，只限制依赖它的判断，不把整篇论文全盘否定。
- 先从原文提取，再对照已有卡片和大纲。旧总结用于定位待修内容，不作为原文结论的证据。

### 3.3 先建立少量关键证据记录

无需逐句摘录。只为支撑主要结论和重要争议的证据设局部编号，如论文页 E1、E2，记录一次并被其他页面引用。

| 字段 | 要求 |
|---|---|
| 内容与类型 | 直接观察/测量、计算/模型输出、作者机制解释、转引文献、AI 推断，允许分别列出 |
| 对象与必要条件 | 哪个样品、处理条件、时长、对照、实际覆盖组合；缺失写未报告 |
| 指标与结果 | 测量起止点/操作定义、单位、近似值、误差及其含义；图上估读必须标估读 |
| 来源定位 | 图/表/章节，必要时页码；注明本地 PDF 页序与印刷页码差异 |
| 支持范围 | 该证据支持什么，不能证明什么，是否有替代解释或相反观察 |
| 核查状态 | 已回查、仅转录、依赖未得附件、待核查；不与支持强度混写 |

条件采用“通用必要字段＋任务相关扩展”，避免所有论文都填写陶瓷实验表。当前项目可在 project_profile 中保存 CMAS 阅读清单：温度、保温/冷却、配方计量口径、负载、储池/流失、块体/涂层、密度/孔隙/晶粒、晶型、层厚与渗透定义、测量或计算，以及 EBC/TBC 应用目标。

### 3.4 评价结果与机制

每个核心判断依次核对：

1. 原文到底观察或计算了什么？样品与时长覆盖是否完整？
2. 对照是否同条件，是否来自另一个实验或旧文？有多少独立数据来源？
3. 误差、重复数、检测限、缺失数据是否支持措辞？未报告不能补造；无统计依据不称“显著”。
4. 作者解释是否被直接验证？组成、结构、孔隙等变量是否同时变化？
5. 还有哪些合理解释？不要求穷举，但检查足以改变主结论的解释。
6. 哪些条件内可以保留结论，哪些外推需要暂缓？

单篇研究可以对一个限定实验事实提供强支持，无需机械要求多篇；多篇转引也不构成独立强证据。局部 TEM、单个对照或未见析出，只支持其采样范围与检测条件。计算的应力、热力学量或热物性不能自动写成实测值；形成焓不能直接等同于完整反应自由能或动力学。

### 3.5 生成平衡的论文总结

正文优先保留：研究问题、实验/论证设计、主要结果、作者解释与证据评价、适用边界、贡献和可复用结论、未决问题。

摘要改写最后完成，确保没有比证据表更强的表述。贡献应讲清楚论文实际增加了什么认识；既不照搬“首次/最佳”，也不将所有机制解释都贬为无价值。多目标材料设计分别报告收益与代价，不以单一指标代替全部性能。

“作者声称的创新”与“本次阅读能够确认的贡献”分开。缺少领域检索时不确认首创性；没有有价值的 gap 可以不生成 gap。局部修改只改变受影响段落，不强制重新填满全部模板。

## 4. 入库、综合与大纲的质量要求

### 4.1 入库完成不等于所有判断已解决

保留已有 processed 表示已建立卡片，增加独立的复核状态约定，例如 draft、checked、needs-review；最终字段名与枚举在实施时统一。checked 只能表示声明范围内已检查，仍可包含明确标识的未决证据。

主要结果必须有定位、条件和证据类型。未读关键材料、来源身份不清或核心表述有冲突时，可保存草稿与已确认部分，但不能把未确认核心结论升级为可信 claim。

### 4.2 Claim 的来源与更新

- 一个 claim 表达一个可检验判断，不把实验趋势、机制、筛选建议和寿命预测捆成一个高置信度结论。
- 用论断级证据记录解释支持程度；不用“论文质量高”“有六篇链接”代替论证。
- 转引应回指最初数据来源；未独立阅读原始引用时明确为转引，不伪装完整验证。
- 来源修订后查找直接受影响页面，标记待复核及原因；允许稍后逐项更新，但受影响旧判断不得再作为确定依据。
- 每篇保存轻量修订编号/日期和已检查依赖即可；先不引入复杂版本数据库或每次全库哈希扫描。

### 4.3 跨论文比较

综合前建立小型矩阵：研究问题、材料/结构、实验条件、指标定义、结果、数据来源与独立性、局限。比较分为：可直接定量比较、仅能限定性定性比较、暂不可比较。

“排名相反”先排查指标、坐标方向、条件、样品和数据来源，再判断是真冲突还是条件变化。不得把不可比数字合并拟合或求倍数；不得因为不同系统都形成某种产物就宣称同一机制。

语料集中于同一研究组时，明确代表性边界，不能称领域共识。topic 的 Current Consensus 应改成可容纳“当前语料支持的认识”，method 只记录已验证用途和限制。

### 4.4 Gap 与研究定位

分开保存：作者自述局限、当前语料缺口、AI 提出的候选研究问题，以及经过限定范围检索仍未解决的问题。若后续要声称领域 gap，记录检索日期、范围、检索式/来源和反例；结论仍限于覆盖范围，不保证绝对无人研究。

每个候选问题说明已有工作解决到哪里、剩余变量为何重要、什么证据可回答、可行性和反证。用户目标不明确时采用显式暂定问题，不替用户确定博士选题。

### 4.5 大纲从证据生成

先有研究问题和比较矩阵，再提出候选主线，最后组织大纲。每节列出：要回答的问题、已核查的证据、允许的论断、适用边界与缺失部分。

主线的核心前提失去支持时，先修改或撤回主线，再重组章节；不通过补充措辞维持原有叙事。没有足够证据时，允许输出暂定结构，不强行写成“统一规律—规律失效—新判据”的确定故事。

## 5. 分步实施计划

每一阶段均可拆成一次只修改 1–3 个核心规则文件的小任务。索引、日志和必要的错误/决策记录随任务维护；本计划不要求每一步新增人工审批。用户要求逐步开展，完成当前步骤后先展示具体差异与验证结果，不自动开展下一阶段。

| 阶段 | 修改对象 | 完成内容 | 验收标准 |
|---|---|---|---|
| 1. 统一质量底线与任务边界 | memory/hard_memory.md、AGENTS.md | 定义证据类型、核查/强度区别；明确新入库、完整复核、局部修订的范围；公共规则只定义一次 | 同一论断能区分实测与解释；局部修订无需触发整库更新；原始资料与既有授权边界清楚 |
| 2. 重建论文阅读和输出流程 | agents/pdf_read_agent.md、templates/pdf_ingestion_template.md、templates/paper.md | 把第 3 节落实为阅读步骤、简短质量清单和精简卡片；加入关键图表回查与覆盖声明 | 不重复生成两份长卡片；核心结论均有条件、指标、定位与评价；无法确认的信息保留为未决 |

| 9. 单篇试运行 | 2019 RE2SiO5 论文，后续另行安排其受影响页面 | 用新流程逐节修订；检查数据、解释、结论与下游待复核标识 | 修订可逐条对照来源；原始文件不动；尚未修订的下游明确待复核；确认有效后再安排其他六篇 |

## 6. 验收案例与迁移策略

以下来自前期复核，用于检验新规则是否能阻止旧错误；本计划不替代这些论文的正式修订。

| 案例 | 新规则应产生的结果 |
|---|---|
| 衰退层厚度与最深渗透深度作四倍比较 | 标记指标/条件不同；不把比值写成确定温度效应 |
| 作者引用形成焓解释反应趋势 | 保留机制解释，注明转引与外推；不冒充本文直接量热 |
| 高温视频说明未见析出 | 限定为观察窗口未见可辨析出，不推断无化学反应 |
| 多篇文章引用同一 1300 °C 数据 | 识别共同来源，不能算多次独立复现 |
| 高熵材料热学表现较好、抗蚀未超过最佳单组分 | 写成多目标折中，避免“全面优于” |
| 热应力由简化公式计算 | 标明计算假设，不写成实测失效应力或已验证循环寿命 |
| 七篇未覆盖某条件 | 记为语料缺口或候选问题；领域新颖性待检索 |
| 论文 frontmatter 的 type 为 topic | 结构检查报错；不会因 YAML 可解析就通过 |
| 原始 claim 被修正，大纲还在引用旧版本 | 下游标记待复核，不能继续把旧结论当成确定前提 |

迁移以保留路径和历史为原则，不批量删除、重命名、升级全部旧页面。现有七篇不能因新增状态字段就默认变成 checked；在逐篇复核时填写。日志保留历史错误描述，并用后续纠错记录说明替代关系。先不建立新的 evidence 数据库目录，关键证据表留在论文卡片内。

基础自动校验仅负责确定性问题：YAML 结构、目录/type、字段缺失原因、DOI 重复、链接和状态值。来源是否真正支持结论、变量是否混杂、大纲是否迎合旧主线仍需语义审查，不能靠正则或勾选清单保证。
