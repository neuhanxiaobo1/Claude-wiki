# Lint Agent

本规程负责结构、证据和流程检查，公共标准以 `memory/hard_memory.md` 为准。结构合格不代表科学结论正确。

## 方向绑定与路径约定

方向内检查先遵循根目录AGENTS.md绑定本会话方向，再显式读取 `D/AGENTS.md`；公共架构检查直接按根规则和本轮范围执行，无须绑定科研方向。D是已注册方向的真实根路径；未选方向不能写研究文件。根目录agents/templates/memory/hard_memory是公共规则；本文project_profile、研究index/log/inbox及错误记录均属于D，词表采用公共层加本方向词表。仅使用本方向声明的阅读/综合/写作扩展，未声明则沿用通用流程。模板中的D与direction_id必须展开，生成双链使用vault完整路径。

默认读写范围限D；另一方向资源只按具体需要定向读取、来源方向默认只读。跨方向同DOI页面可以独立存在，但同一原始数据不能重复计为独立验证。去重/别名合并限本方向。公共架构lint无需科研方向，写入根级维护记录；单方向任务不得更新其他方向。

## 1. 范围与启动

- 复用 AGENTS 和 context_policy 的增量读取规则；只读本轮对象、对应模板及相关错误记录。检查标签/别名时才读取对应词表，不默认加载全部历史和综合页。
- 区分“完善检查规则”和“实际检查知识页”：前者不自动启动整库迁移。实际 lint 默认覆盖 wiki、synthesis 与必要索引；用户指定局部范围时只检查该范围，引用目标只作必要的只读核对。
- 声明检查对象、层次（结构/证据/流程）、采用的规则版本、覆盖范围和未检查部分。不因信息缺失停止独立可完成项。
- 检查模板、说明文档和真实知识页时分开处理。模板是生成目标格式，不能按真实论文的必填值检查；示例区和代码块中的占位链接不算真实失效链接。

## 2. 结构检查

| 项目 | 判据与处理 |
|---|---|
| Frontmatter | 检查 YAML 语法、重复键和字段类型；简单文本搜索不能声称完成 YAML 解析。无 frontmatter 的旧页列迁移项，不编造元数据 |
| 目录与 type | D/wiki/papers → paper，authors → author，topics → topic，methods → method，datasets → dataset，metrics → metric，claims → claim，gaps → gap，reviews → review；synthesis 按页面用途判断，不机械要求全部 type: synthesis |
| 最小字段 | 新建/完整复核按对应模板检查 type、标题或明确页面标题、status、tags；paper 还核对 title、来源身份及实际来源路径/标识、DOI/Zotero key 的适用性和已知值。未报告、非 Zotero 来源或确无 DOI 不自动判错 |
| 核查字段 | paper/claim/topic/method/gap/review 的 review_status 若使用，取 draft / checked / needs-review；旧页缺字段先列待迁移，不自动填 checked。正文等价记录按 hard_memory 接受；与 YAML 冲突则报告 |
| 链接 | 验证真实双链与本地 Markdown 链接的文件目标；标题锚点、块引用与显示别名分别解析。同名短链有多个目标时报告歧义。目录导航不是缺失知识页，不自动建页 |
| 证据定位 | 有效文件链接与有效证据定位分开。E# 是证据记录标识，需确认目标记录或等价原文定位存在；并非任意 E# 都是可点击标题锚点。形如双链结束后附 #E1 的文字不能算已验证的跳转 |
| 标签与别名 | 对照词表检查大小写、同义标签、未登记标签；领域相近不等于同义，重名也不等于同一科学判断 |
| 导航与重复 | 重要页面是否可从 index 找到，索引描述是否仍准确；孤立、单向链接仅是检查线索，不要求互链或制造新关系。同 DOI/item key 或近似标题只提示核对版本/身份 |

占位值规则：真实页面中决定身份或结论的 {{占位符}}、空字段、YYYY-MM-DD 等列为未完成/待迁移；明确的“未报告”“待核查”保留其语义，不为消除告警补造数据。模板和显式示例中的占位值不作真实数据错误。

## 3. 证据检查（需阅读判断，不能靠字段存在判定）

- 沿具体论断 → paper E# 或等价定位 → 原文核查，记录实际覆盖。未读取原文只能报告缺字段/断链或疑点，不能宣布证据充分。
- 分开证据类型、支持程度和核查状态；processed、strong、链接数量均不能替代原文核查。checked 也不等于 supported。
- 检查对象、必要条件、指标定义、单位、误差与来源是否匹配；实测、计算、作者解释、转引和 AI 推断不得互换。
- 跨论文比较检查比较资格和原始数据独立性；共同转引不重复计数，指标不同不求倍数或统一排名。
- claim 检查判断边界、支持理由、反证和未决项；topic/method 检查语料覆盖与适用范围，不能从本地语料推成领域共识或普适方法。
- gap 按模板区分 paper-limitation / corpus-gap / candidate-question / scoped-field-gap；领域 gap 须有范围明确的检索记录，关键词或页数不足以证明新颖性。
- review/大纲检查论断到证据的对应、章节 readiness 与主线前提；前提失效不得只加免责声明保留原叙事。
- 已知错误影响下游时列出具体页面/论断、原因、来源与处置状态；范围外问题记在源页或维护记录，后续使用前必须解决。

## 4. 流程检查

- 对照本轮任务授权和日志检查实际变更，不把历史单次上传、入库或重命名授权扩展到新动作；已有明确授权不重复询问。
- 仅在 collection 导入任务涉及生成清单时检查 import_plan/manifest 的一致性、条目身份、去重和处理状态。已知论文局部修订无需新建 collection 清单。
- DOI、item key 按来源适用性核对；清单“已入库”只表示卡片存在，不表示科学复核完成。
- 检查是否改动原件；生成的导入管理记录与原始 PDF/缓存按 hard_memory 区分，不扩张 Zotero 写权限。
- 重要操作有 log；实际错误有 error_log；只有成员、路径、说明或重要状态变化才需更新 index。
- 恢复机制归根context_policy，方向当前任务与恢复入口归 D/memory/current_context.md，研究目标归 project_profile，科学主张归 synthesis；不因继续阶段而强制压缩或改写科学页。
- 历史决策按日期、适用范围和状态解释，不能将开源发布约束作为清理当前私人库的指令。

## 5. 发现与修复

每项发现使用简短记录：

| 位置/论断 | 层次 | 依据与影响 | 优先级 | 处置/下一步 |
|---|---|---|---|---|
| 实际文件及字段或段落 | 结构/证据/流程 | 检查到的事实；未验证部分另标 | 阻断当前结论 / 待修复 / 提示 | 已修复 / 待复核 / 因材料缺失暂无法核查 / 不适用 |

- 优先级取决于当前任务影响：错配来源或失去关键前提可阻断结论；缺选用标签、孤立页不应阻断论文阅读。
- 授权范围内可直接补索引、日志或修正确定的格式错误。标签替换须确认含义相同；不把所有未登记标签自动吸收进词表。
- 合并、删除、重命名重要页面需已有明确授权；没有时先列具体候选、信息保留方案和受影响链接供确认。不得删除原件。
- 旧页面逐篇/逐论断迁移：保留路径、正确内容和来源；局部修订只补必要字段，不强制重填模板。格式迁移不能提升证据状态。
- 不从 type 错误推断论文内容错误，也不从修正 type 推断内容正确。无法确定正确值时保留待核查。

## 6. 验收与汇报

- 结构检查至少用这些桌面案例核对：papers 中 type: topic；关键来源字段缺失；真实链接目标不存在；模板示例占位。这四类分别应被识别为类型错误、缺失/待迁移、断链、示例豁免。
- 证据案例：字段完整但原文未读，应报告“结构检查完成，证据未核查”；processed 且缺 review_status 的旧页不得自动升级。
- 修复后只复查受影响项目及必要引用。自动工具必须说明支持的语法、排除范围和未实现检查；不把简单正则匹配报告为全面 lint。
- 汇报范围、实际发现、已修复项与遗留项；无关输出栏目可省略。重要任务追加 log、错误记录和必要的状态更新。
